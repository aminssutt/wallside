Finding the right manual

A chatbot answering from car owner manuals has to find the right document first, then the right page. We measure how well it does that as the library grows, which techniques hold up, and when asking one question beats guessing.

00 · QUESTION

What we set out to measure

For every user question the system must retrieve the right manual (which vehicle) and the right passage (which page). Both are measured separately, with 95% confidence intervals, while varying three things: how many manuals are searched, the retrieval technique, and how much the question says about the vehicle.

DATA · CORPUS

The library and the exam

The corpus is extracted verbatim from the production indexes: manuals, passages, pages, vehicles, French manuals and English ones.

Data defects found along the way

    The exam: questions whose answer page is known

    For each manual, a Gemini model (, a different generation from the production model) writes an owner-style question, its answer and a verbatim quote from the passage. A question is kept only if that quote really appears in the passage. Every question exists in eight forms: French or English, with no vehicle, with the brand, with the model, with the full name.

    E4 · CLARIFICATION

    “How do I change my battery?”: ask before searching

    With no vehicle named, that question has up to different answers, one per vehicle. No retrieval technique can guess the car. We turn it into a three-way decision, as in the recent adaptive-RAG literature: answer ask abstain.

    flowchart TD
    q([Question]) --> m{Brand absent from the corpus?}
    m -->|yes| a1[ABSTAIN: manual not available]
    m -->|no| t{Max similarity below the 1st percentile of real questions?}
    t -->|yes| a2[ABSTAIN: off-topic]
    t -->|no| v{How many vehicles does the question name?}
    v -->|exactly one| r1[ANSWER inside that vehicle]
    v -->|several versions| c1[ASK: which version?]
    v -->|none| d{Detector: does the answer depend on the vehicle?}
    d -->|no| r2[ANSWER across all manuals]
    d -->|yes| c2[ASK: which vehicle? 3 options + free text]

    Spotting ambiguity: yes. Knowing whether it matters: no.

    ARCH · RECOMMENDATION

    The pipeline the measurements recommend

    flowchart LR
    Q[Question] --> D{Decision agent}
    D -->|unknown brand or off-topic| A[Abstain]
    D -->|answer depends on the vehicle, none named| C[Clarifying question]
    C -->|user picks one| F[Filter to that vehicle's manuals]
    D -->|one vehicle named| F
    D -->|generic question| G[All manuals]
    F --> S[Strip the vehicle name from the query]
    S --> R[Hybrid retrieval 0.3 BM25 + 0.7 bge-m3]
    G --> R
    R --> L[LLM answer with cited pages]

        METHOD · REPRODUCIBILITY

        Method

        • Metrics. Right manual at rank 1 (doc_hit@1), right passage in the top 5 (chunk_hit@5), nDCG@10, confusions with a manual of the same brand. A passage counts as right when it contains the reference quote; the computation is cross-checked against the ranx library.
        • Statistics. The question is the unit of analysis (random draws are averaged per question). Wilson 95% intervals for proportions, bootstrap otherwise; paired comparisons by randomization test with Holm correction.
        • Protocol. Settings (fusion weights, thresholds) are chosen on the dev split and every figure in this report comes from the test split. The off-topic threshold is calibrated on in-domain questions only.
        • Reproduce. make corpus embed dataset, then ragscale run configs/e1_scaling.yaml, ragscale clarify configs/e4_clarification_partial.yaml and python scripts/build_report.py. Code on branch research, directory research/.
